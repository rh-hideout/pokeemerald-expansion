# Mass outbreaks

## Vanilla mass outbreaks

After you've beaten the game, there is a one in 200 chance everytime you finish a battle to add a mass outbreak program to the list of active tv shows. When adding a mass outbreak program, the game will roll a random mass outbreak from the mass outbreak table and add it to the tv show data. After two days have passed, if there is no mass outbreak active in the overwold, you can watch the mass outbreak program on TV and this is start the mass outbreak that you rolled earlier.

## Expansion features

### Shiny bonuses

`WE_MASS_OUTBREAK_SHINY_BONUS` in `include/config/wild_encounter.h` enables Scarlet/Violet's outbreak Shiny bonuses when set to `GEN_9` or higher. Earlier generations disable the bonus.

| Outbreak Pokémon defeated or caught | Additional Shiny rolls |
| --- | --- |
| 0–29 | 0 |
| 30–59 | 1 |
| 60 or more | 2 |

These rolls stack with the Shiny Charm and lures. Only Pokémon generated by the outbreak receive the bonus; ordinary encounters of the same species do not. The bonus is applied when an overworld encounter spawns, and its displayed shininess is preserved when its battle starts.

Progress belongs to the active outbreak and is saved separately from fishing and DexNav chains. Running away, unrelated battles, and leaving the map do not reset it. Starting or replacing an outbreak, clearing it, letting it expire, or editing its species or location resets progress. Editing its level, moves, probability, or remaining duration preserves progress unless the duration is set to zero. The counter stops at 60; this feature does not add outbreak depletion.

DexNav searches temporarily suppress outbreak encounters without resetting outbreak progress. Starting a search removes generated overworld encounters for every search entry point, including the registered shortcut. Existing outbreak objects cannot start an encounter through collision or interaction while the search is active.

Use `getmassoutbreakdata VAR_RESULT, OUTBREAK_DATA_CLEARED_COUNT` to read progress. Existing saves without outbreak progress start at zero. The counter and its version marker occupy previously unused outbreak bytes, without changing the save block layout.

Mechanics reference: [Mass outbreak, Pokémon Scarlet and Violet](https://bulbapedia.bulbagarden.net/wiki/Mass_outbreak#Pok%C3%A9mon_Scarlet_and_Violet).

### Base Shiny chance

`P_SHINY_CHANCE` in `include/config/pokemon.h` selects the base chance for newly generated Pokémon whose original Trainer is the player, including wild encounters, gifts, and Eggs. `GEN_5` or earlier gives 1/8192 per roll; `GEN_6` or later gives 1/4096. The default is `GEN_LATEST`.

For custom odds, replace the expression in `P_SHINY_THRESHOLD` with an integer from 0 to 65536. The probability per roll is that value divided by 65536: for example, 64 gives 1/1024. Zero disables random Shinies and 65536 makes every eligible roll Shiny. Existing force-Shiny settings and explicit script overrides retain their precedence.

Changing these settings does not change the shininess of Pokémon already stored in a save using the standard storage threshold of 8. `SHINY_STORAGE_THRESHOLD` describes the saved format and must remain fixed; it replaces the old `SHINY_ODDS` constant. Preset-OTID creation retains its original personality/OTID behavior, and explicitly non-Shiny creation remains non-Shiny.

### Static outbreaks

The data in the mass outbreak data table has been expanded, properties that previously existed only on the save file for active mass outbreak can now be set in the mass outbreak data table (map group, probability, duration). These were previously fixed in vanilla and can now be changed. The complete list of fields is:

- `species` : the species of the mass outbreak encounter
- `moves` : the moves the mas outbreak encounter has
- `level` : the level of the mass outbreak encounter
- `location` : the map id where the mass outbreak is happening
- `probability` : the percent chance you get a mass outbreak encounter instead of a regular wild encounter
- `duration` : the number of days the mass outbreak will last

All the properties are preserved even when the outbreak is started the "vanilla" way. Because they are stored in a ROM table and immutable, they are referred as static outbreaks. However expansion also adds the possiblity to create new outbreaks at run time or change outbreaks that are already happening. We call those dynamic outbreaks.

### Dynamic outbreaks

You can interact with outbreak through script commands or through the debug menu (Encounters -> Mass Outbreaks submenu).
The following commands are available to the user:

 - `startoutbreak` : starts an outbreak (will not work if there is already an active outbreak). Can start an active outbreak is used with  a number/constant `startoutbreak OUTBREAK_ROUTE102` or can start a dynamic by specifying each parameter
 - `editoutbreak`: changes the properties of an active outbreak
 - `clearactiveoutbreak`:  ends the current active outbreak
 - `checkhasactiveoutbreak`: sets var result to TRUE if a outbreak is active and FALSE if there is no active outbreak
 - `getmassoutbreakdata`: allows you to set the properties of the active outbreak into a variable


#### `startoutbreak` / `editoutbreak`

When starting or modifying an outbreak, the function is by default called with these values
`species=SPECIES_NONE, level=0, move1=MOVES_COUNT, move2=MOVES_COUNT, move3=MOVES_COUNT, move4=MOVES_COUNT, probability=0xFF, daysLeft=0x3FFF, map=MAP_UNDEFINED`

These are default values that tells the game nothing needs to change. So you can set one, multiple or all values at the same time when calling the command.
